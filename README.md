# AI先行者 GEO 运营中台

这是一个可本地运行的 CRM + GEO 全栈后台。CRM 客户管理通过“小人”入口选择 GEO 产品，带入客户身份后进入 AI先行者全域 AI 搜索工作台。

## 在线演示

[https://yanruwill-dot.github.io/ai-pioneer-geo/](https://yanruwill-dot.github.io/ai-pioneer-geo/)

备用公网入口：[https://ai-pioneer-geo.netlify.app/](https://ai-pioneer-geo.netlify.app/)

本机稳定入口：[http://127.0.0.1:3306/](http://127.0.0.1:3306/)。当前 Mac 已配置 `com.ai-pioneer.geo-console` 常驻服务，登录后会自动启动并在异常退出后拉起。

GitHub Pages 版本使用浏览器本地数据层，因此登录、客户切换、新建、筛选、状态流转和配置保存均可操作，刷新后仍可回查。在 Pages 上使用 Hash 路由，所有站内页面都从同一个 `200` 入口加载，避免静态托管对深层路径返回 `404`。演示数据只保存在访问者自己的浏览器，不会写入生产系统。

- GEO 数据驾驶舱：收录、搜索词、平台、直接转化曝光等按采样明细自动派生的指标
- 可追溯效果指标：AI 提及率、被引用概率、全样本引用率、基线周期对比、平台拆解和拓展词出现场景
- 关键词营销定位、企业知识库、发布任务的新增和持久化
- 自动化任务启停

- 实名认证与 AI 智能体配置保存
- 转化目标、媒体授权、提示词、批量创作、文章与视频工作流
- 深层页面状态筛选、新建、详情查看和状态流转
- AI 搜索竞争力分析报告
- 响应式桌面与移动端布局
- SQLite 本地数据库、API 集成测试、生产构建

## 数据边界

当前版本是独立可运行系统，没有接入对标站生产数据库，也不会修改其客户数据。驾驶舱和深层页面的首批记录主要来自本地种子数据，新增客户、关键词、知识、配置和业务记录会写入 `data/geo.sqlite`。系统另保存了一条来自用户豆包历史会话的真实回查样本，包含原始问题、回答正文、采集时间、参考资料数量和原始会话 URL；其正文属于模型输出，不代表项目对其中事实背书。持续的真实大模型采样、内容生成和对外媒体发布仍需接入对应服务商凭证与平台授权。

### 效果指标口径

- **AI 提及率** = AI 回答明确提及品牌的采样数 ÷ 全部采样数。
- **被引用概率** = 在已提及品牌的采样中出现官网、链接或可验证信源的采样数 ÷ 已提及采样数。
- **全样本引用率** = 出现直接引用或转化目标的采样数 ÷ 全部采样数。
- **基线对比**按采样日期自动拆分为前半段基线周期与后半段当前周期，页面展示“从多少到多少”和百分点变化，不写死增长数字。
- **拓展词场景**根据关键词分类聚合为需求检索、问题求解、行业比较和本地决策，并可回查到每个问题词的平台样本。

外部采样器或平台回查程序可以通过 `POST /api/observations` 写入平台、问题词、设备、排名、提及、引用、情感、采样时间，以及可选的回答正文、平台原始 URL、参考资料数量、采集时间和转化目标；接口会强制把“未提及但被引用”的矛盾记录归零，避免概率超过 100%。当前仓库内置数据用于演示和回归测试，接入真实平台采样后，驾驶舱会按同一口径实时重算。

“快照凭证”证明的是当前工作区中存在一条可定位、可按客户隔离回查的采样记录。已保存原始回答全文和平台 URL 时，凭证页会展示保存正文并允许跳到原始会话；若采样器没有保存这些内容，页面会明确显示“当前记录未保存”，不会把系统生成摘要冒充平台原始证据。原始平台链接可能要求平台登录，平台回答也可能包含错误；页面一致性校验码不等同于数字签名或第三方存证。

GitHub Pages 是静态演示部署，不运行 Express/SQLite 服务；它通过 `src/demoApi.js` 在浏览器本地模拟相同业务接口，并按客户分开保存工作区数据。需要多人共享数据库、账号级权限或真实发布时，应部署完整 Node.js 服务。
